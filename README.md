# INNTEK ENVIRONMENT

Внутренняя информационная система производственного предприятия.
Разрабатывается под задачи одной компании — производителя курьерских пакетов.

Система автоматизирует процессы от приёма сырья до отгрузки готовой продукции клиенту:
производство, упаковка, этикетирование, склад, контроль качества, отчётность.

---

## Что это

Малый MES (Manufacturing Execution System) — лёгкая система управления производством,
развёрнутая локально на предприятии. Не облако, не SaaS. Все данные — на территории
компании. Интернет не требуется.

Система развивается модулями. Каждый модуль самодостаточен, но опирается на общее ядро
(пользователи, смены, справочники, логирование). По мере роста модули связываются между
собой и образуют сквозную логику: **сырьё → производство → упаковка → склад → отгрузка**.

---

## Для кого

- **Оператор-наладчик** — открывает смену, запускает станок, печатает этикетки.
- **Упаковщик** — упаковывает пакеты в коробки, клеит этикетки, собирает паллеты.
- **Кладовщик** — принимает продукцию, комплектует заказы, отгружает.
- **Начальник смены / руководитель** — видит выработку, качество, остатки в реальном времени.
- **Инженер-механик** — управляет справочниками, оборудованием, регламентами.

---

## Ключевые принципы

1. **Локальность.** Сервер стоит на предприятии. Данные не покидают компанию.
2. **Простота.** Минимум зависимостей. Понятный стек. Один разработчик может поддерживать.
3. **Расширяемость.** Новые модули добавляются без переписывания существующих.
4. **Практичность.** Каждый модуль решает конкретную боль производства.
5. **Открытость.** MIT-лицензия. Можно передать, продать, доработать.

**Взаимодействие:** backend генерирует TSPL (или PNG) для этикетки и отправляет POST-запрос
на LabelJetty. LabelJetty принимает задание, ставит в очередь и печатает через USB.

(сканирование штрихкодов через веб-форму). Все — в одной локальной сети.

## Что уже работает

### Ядро

- Развёртывание одной командой `docker compose up` (Docker + PostgreSQL + FastAPI).
- Справочники:
  - **Пользователи** — ФИО, табельный номер, роль, PIN.
  - **Станки** — КП1..КП5 (расширяемо).
  - **Спецификации** — SKU из 1С, размеры, цвет, толщина плёнки.
  - **Шаблоны этикеток** — TSPL-макеты (ВБК, МП, СДЭК).
  - **Варианты этикеток** — связка спецификации и шаблона (что печатать на конкретный SKU).
- Полный CRUD через REST API для всех справочников.

### Смены

- Открытие/закрытие вручную оператором-наладчиком.
- Состав: оператор, помощники, стажёры.
- Только одна активная смена.
- PIN-код для входа.

### Упаковщики

- Привязка к станку через ТСД по PIN.
- Защита от двойной регистрации.
- Смена упаковщика в течение смены (с указанием причины).
- Возможность нескольких упаковщиков на одном станке.

### Этикетки

- Создание коробки с уникальным UID, QR-кодом, номером в смене.
- Генерация TSPL по шаблону с подстановкой данных.
- Отправка в LabelJetty → печать на TSC TE200.
- Три направления: ВБК, МП, СДЭК.
- QR читается мобильными телефонами.

## Что планируется

### Ближайшее (в работе)

- **PrintRun** — печать партией (10/50/100 этикеток за один заход).
- **Веб-интерфейс** — для оператора, упаковщика, кладовщика. Сейчас всё через API.

### Среднесрочное

- **Паллеты** — агрегация коробок в паллету, перепечатка паллетных этикеток.
- **Клиенты** — Wildberries, СДЭК, Спортмастер и др. как сущности.
- **Производственные задания** — что делать в смену, на каком станке.
- **Партии сырья** — учёт плёнки, лайнера, клея, риббона.
- **Складской учёт** — движения, остатки, приём/выдача.
- **Контроль качества** — чек-листы, изоляция брака (регламенты 4.2, 4.3).
- **Отчёты** — по смене, станку, сотруднику, заданию.

### Долгосрочное

- **Аудит** — журнал всех действий пользователей.
- **Планирование производства** — планы на неделю/месяц.
- **Интеграция с 1С** — синхронизация SKU, клиентов, заказов.
- **Второй принтер** (58×40) — маршрутизация по профилю.

### Требования

- Docker Desktop (или Docker Engine + Compose на Linux)
- Git
- Для устройства с принтером: Python 3.12 + LabelJetty (см. `printer_service/`)

### Первый запуск

```powershell
git clone https://github.com/r3tr0-hub/inntek-environment.git
cd inntek-environment
copy .env.example .env

Открыть .env, вписать реальные значения:

    POSTGRES_PASSWORD — надёжный пароль для БД.

    JWT_SECRET — случайная строка 32+ символа.

Запустить:
docker compose up --build -d

Проверить:

    http://localhost:8000/ — статус backend.

    http://localhost:8000/docs — Swagger (тёмная тема).

Настройка LabelJetty (на ноуте с принтером)

См. printer_service/README-INNTEK.md.
